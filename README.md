# GitaSaar — श्रीमद्भगवद्गीता

> Bhagavad Gita in Sanskrit, Marathi & English with four commentaries. Free, open, deployable.

## Quickstart

```bash
# 1 — Install frontend dependencies
cd app && npm install

# 2 — Fetch Gita data (one-time, runs on your machine only)
cd ../data-collection
bash setup.sh                          # creates .venv and installs deps (macOS / Linux)
source .venv/bin/activate
python3 fetch_gita_data.py             # writes app/public/data/chapter-*.json

# 3 — Start dev server
cd ../app && npm run dev               # → http://localhost:5173

# 4 — Deploy to Vercel
vercel --cwd app
```

> **Apple Silicon Mac (M1/M2/M3)?** If `npm run dev` fails with `Cannot find module @rollup/rollup-darwin-arm64`, the `package-lock.json` was built on a different OS. Fix with:
> ```bash
> cd app
> rm -rf node_modules package-lock.json
> npm install
> ```

> **Windows?** Skip `bash setup.sh` and run manually:
> ```cmd
> cd data-collection
> python -m venv .venv
> .venv\Scripts\activate
> python -m pip install -r requirements.txt
> python fetch_gita_data.py
> ```

## Data Collection

The Python script scrapes Gita data from freely-licensed academic sources and writes static JSON files used by the frontend.

### Setup (macOS / Linux)

```bash
cd data-collection
bash setup.sh              # detects python3, creates .venv, installs deps
source .venv/bin/activate
```

### Run

```bash
python3 fetch_gita_data.py          # all 18 chapters (~700 verses)
python3 fetch_gita_data.py 1 3      # chapters 1–3 only (faster for testing)
```

### Manual install (alternative to setup.sh)

```bash
cd data-collection
python3 -m venv .venv
source .venv/bin/activate           # macOS / Linux
# .venv\Scripts\activate            # Windows
python3 -m pip install -r requirements.txt
python3 fetch_gita_data.py
```

### Sources

| Source | Content fetched |
|---|---|
| IIT Kanpur Gita Supersite | Sanskrit · transliteration · Sivananda & Bhaktivedanta translations · Marathi · all four commentaries |
| vedabase.io (fallback) | Bhaktivedanta purport when IIT Kanpur is unavailable |

All content is public-domain or openly licensed. See `LICENSE` for details.

**Output:** `app/public/data/index.json` + `app/public/data/chapter-1.json` … `chapter-18.json`

Sample data for Chapters 1 and 2 (select verses) is already included so the UI works without running the script.

app/public/images/krishna.jpg

## Deployment (Vercel)

### Option A — Vercel CLI

```bash
npm i -g vercel          # install CLI once
cd gitasaar
vercel --cwd app         # follow prompts; select "app" as root
```

### Option B — Vercel Dashboard (recommended for CI/CD)

1. Push the repo to GitHub.
2. Go to [vercel.com/new](https://vercel.com/new) → Import your repo.
3. Set these values in the project settings:

| Setting | Value |
|---|---|
| **Root Directory** | `app` |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |
| **Install Command** | `npm install` |

4. Click **Deploy**. Vercel detects Vite automatically.

The `app/vercel.json` configures:
- SPA routing (`/* → /index.html`) so React Router works on page refresh
- `Cache-Control: public, max-age=86400` on `/data/*` (chapter JSON files)
- `Cache-Control: public, max-age=31536000, immutable` on `/images/*`

### Re-deploying after fetching new data

```bash
# 1. Run the scraper locally
cd data-collection && python3 fetch_gita_data.py

# 2. Commit the generated JSON files
cd ..
git add app/public/data/
git commit -m "chore: update Gita data"
git push                 # Vercel auto-deploys on push
```

## REST API (client-side, no backend)

A **Service Worker** (`public/sw.js`) intercepts browser `fetch` calls to `/api/*` and serves data from cached JSON files — no backend, no server, fully Vercel-compatible.

### Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/api` | API info + endpoint list |
| `GET` | `/api/chapters` | All 18 chapters (metadata) |
| `GET` | `/api/chapters/:id` | Single chapter metadata |
| `GET` | `/api/chapters/:id/verses` | All verses in a chapter |
| `GET` | `/api/chapters/:id/verses/:vid` | Single verse (full) |
| `GET` | `/api/chapters/:id/verses/:vid/translations` | All translations |
| `GET` | `/api/chapters/:id/verses/:vid/translations/:lang` | One translation |
| `GET` | `/api/chapters/:id/verses/:vid/commentaries` | All commentaries |
| `GET` | `/api/chapters/:id/verses/:vid/commentaries/:author` | One commentary |
| `GET` | `/api/search?q=:query[&chapter=:id]` | Full-text search |

`:lang` → `english_sivananda` · `english_bhaktivedanta` · `marathi`
`:author` → `sivananda` · `bhaktivedanta` · `shankaracharya` · `aurobindo`

### Usage

```js
// JS client (tree-shakable, from src/)
import { gitaApi } from './utils/gitaApi'

const chapters = await gitaApi.getChapters()
const verse    = await gitaApi.getVerse(2, 47)
const marathi  = await gitaApi.getTranslation(2, 47, 'marathi')
const results  = await gitaApi.search('karma')

// Or raw fetch — works from the browser console after first page load
const res  = await fetch('/api/chapters/2/verses/47/commentaries/sivananda')
const data = await res.json()
```

> **Note:** The SW is only active in browsers after the first page load. For Node.js access, read the JSON files directly from `app/public/data/`.
